# pstack for Claude Code

This is a generated port of [pstack](https://github.com/cursor/plugins/tree/main/pstack) by Lauren Tan (MIT, see `LICENSE`). It is built from upstream commit `@UPSTREAM_SHA@` of `cursor/plugins`. It also vendors the `deslop`, `control-ui`, and `control-cli` skills from `cursor-team-kit` in the same repository, which is also MIT.

Do not edit files in this directory by hand. They are regenerated by `scripts/pstack/sync.sh` from the sed table, patches, and overlay in `scripts/pstack/`.

## What differs from upstream

- **Models.** Upstream's three model families map to Claude tiers by role: Claude Opus to `opus`, GPT to `fable`, and Grok to `sonnet`. Code delegates and explorers run on `sonnet`. Judgment, prose, and synthesis run on `opus`. Override any of these with `/pstack:setup-pstack`.
- **Panels.** Arena, architect, and interrogate seat `opus`, `fable`, and `sonnet`, and give each seat its own stance. Upstream relies on different vendors having different blind spots. Claude tiers share a lineage, so the stances push the seats apart instead. Expect somewhat more agreement between seats than upstream gets.
- **Cloud agents.** Cursor cloud agents run locally as background subagents with `isolation: "worktree"`.
- **Transcripts.** Skills that read past sessions use `~/.claude/projects/<slug>/<session-id>.jsonl`.
- **No read-only subagents.** Claude Code's Agent tool has no read-only switch. The interrogate reviewers, the arena judge, and the how and why helpers are told not to edit files, but nothing stops them. Commit or stash your work before running those skills so a stray edit is easy to spot and undo.
- **Agent store.** Cursor gives each agent a store directory. Orchestrate state and plan files go to `${XDG_STATE_HOME:-~/.local/state}/pstack/store/` instead, and plan templates point at the installed plugin (`<pstack>/skills/...`) instead of `git show origin/main:pstack/...`.
- **poteto-mode.** Only you can invoke it, as upstream intends. After you run `/pstack:poteto-mode`, a hook adds upstream's one-line reminder to every later prompt in that session.

## Undoing /setup-pstack

`/pstack:setup-pstack` writes `~/.claude/pstack-models.md` and adds one `@pstack-models.md` line to `~/.claude/CLAUDE.md`. To undo it, delete both. Without them, every role uses its default.

## Bumping upstream

1. Set `UPSTREAM_SHA` in `scripts/pstack/UPSTREAM` and run `scripts/pstack/sync.sh`.
2. If sync reports a version change, set `UPSTREAM_VERSION` and `PORT_REV=1`, then rerun. For a port-only change at the same upstream version, increment `PORT_REV` instead.
3. If a patch fails, run `sync.sh --keep /tmp/pstack-work --no-lint`, fix the file in `/tmp/pstack-work/out` by hand, regenerate the patch with `git -C /tmp/pstack-work/out diff sed -- <file>`, and rerun.
4. If the lint fails, add a sed rule for a pure rename or a patch for anything that changes meaning.
5. Skim `git diff plugins/pstack`, because the lint cannot catch Cursor references phrased in a new way. Recheck the skill-name collisions listed in `scripts/pstack/NOTES.md`.
