# Proposal

## Why

Upstream gates 48 of its 49 pstack skills with `disable-model-invocation: true`, and the port keeps that. Claude Code leaves gated skills out of the Skill tool's listing. If the model calls one anyway, the call fails with "Do not replicate this skill's workflow by other means". pstack's playbooks route to sibling skills by name (`` `how` over the subsystem``, "run `/no-comments`", "the **why** skill"). That routing only works today because the model guesses that it can `Read` the sibling `SKILL.md` next to poteto-mode's "Base directory" header.

A headless poteto-mode feature run on 2026-10-04 confirmed this. The model never called `Skill`, read `how`, `architect`, and `arena` by path, and finished the playbook. Two gaps remain:

- **Subagents get no base directory.** `poteto-agent` is told to "Read the `poteto-mode` skill's `SKILL.md`" and has no path. `opening-a-pr.md` has a subagent "run `/no-comments`". `comment-sicko` is told to run `/how` and `/why`.
- **Slash references name a skill the model cannot call.** Eight model-facing places in the playbooks and agents use `` `/no-comments` ``, `` `/unslop` ``, `` `/technical-writing` ``, `` `/how` ``, and `` `/why` ``. A model that takes those literally calls `Skill`, gets the refusal, and drops the step.

The current spec also promises something the platform cannot do. The scenario "Claude loads `pstack:how`" can never pass through the Skill tool while `how` is gated.

## What Changes

- The plugin tells Claude where pstack is installed, and that pstack skills are loaded by reading `<pstack>/skills/<name>/SKILL.md`, never through the Skill tool. Claude gets this in the main session on any turn that invokes a pstack skill, and in every subagent when it starts.
- `<pstack>` gets one definition: the plugin root path that this context injects. The existing "two directories above this skill's base directory" wording stays valid for the main session.
- Upstream skill text is left alone. Bare names, bold names, and slash references keep upstream's wording, so upstream bumps don't conflict. Gating flags still match upstream.
- A headless test drives a pstack subagent through a slash reference to a gated skill and checks that it reads the file without calling `Skill`.
- NOTICE.md explains the routing difference.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `pstack`: "Cross-skill references resolve" changes from "loads the plugin skill" to "Claude reads the referenced skill's `SKILL.md` from the installed plugin, in the main session and in subagents, without calling the Skill tool". A new requirement covers telling subagents the plugin location.

## Impact

- `scripts/pstack/overlay/hooks/`: a new routing-context script, plus new `SubagentStart` and `UserPromptSubmit` hook wiring in `hooks.json`.
- `scripts/pstack/overlay/NOTICE.md`: the routing note.
- `plugins/pstack/` is regenerated by `scripts/pstack/sync.sh`. There are no hand edits.
- Context cost: about 70 tokens in every subagent's context in every project where pstack is enabled, plus the same once per pstack-invoking turn in the main session.
- No change to `renames.sed` or `patches/`, and no new runtime dependency. `jq` is already optional for the existing hook.
